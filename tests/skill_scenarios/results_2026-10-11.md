## Reading

- No plan under either version read sealed data, changed a default or a
  frozen stack, or reported a single split. The gated items held.
- The one outright failure was under the July skills: asked to be ambitious
  about the departure deficit, the agent asked permission to start.
- The difference between versions, about two points in 56, is inside what
  two runs per version can resolve. It is not evidence that the revision
  changes behavior for the better; it is evidence of no regression.

## Limits of this run

- Plans, not observed behavior.
- Claude agents only. The scenarios have not been run under Codex.
- The baseline was not clean: the July-skills agents could see the new
  ledgers and `PROGRAM_STATE.md` in the working tree and the revised skill
  descriptions in the harness listing, and both arms had the July
  `CLAUDE.md` injected by the harness. The first inflates the baseline; the
  second means the revised entry file was not exercised as the always-loaded
  file.
- One grader, one pass. Several PARTIAL grades turn on a strict reading of
  compound expectations.

## What the agents said was unclear

Each agent listed instructions it found unclear, contradictory or stale.
Under the revision these led to about twenty edits made the same day, among them:
what to do when the owner directly asks for a gated action; that blind
reproduction conflicted with a reference file that prints the values; the
missing default margin and seed count for comparing a candidate; who logs a
gate run the owner made by hand; what counts as opaque for row-oriented
dumps; and an under-specified partial-commit recipe. Under the July skills
the agents chiefly reported stale state: a 63-test health count, a "current
agenda" from July, and open data items that were closed months ago.
